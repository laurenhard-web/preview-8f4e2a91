🚀 Куда деплоить проект для удобной приемки с любого браузера/телефона (без ограничений iframe)

Когда игра открыта внутри боковой панели превью чата, она работает во вложенном <iframe>, которому иногда требуется клик для захвата фокуса клавиатуры. Чтобы открывать стенд напрямую по прямой ссылке в отдельной вкладке браузера (с мгновенным фокусом клавиатуры и версионностью по эпохам v1..v6), доступны 3 готовых контура деплоя:

Вариант деплоя Как работает и Безопасность Главные плюсы
1. VPS по секретной ссылке (Рекомендуется для приватной приемки)
https://ваш-домен/s/<UUID-токен>/		 На вашем VPS (Nginx / Caddy) создается закрытый префикс /var/www/previews/<secret_uuid>/ с отключенным листингом директорий и заголовком X-Robots-Tag: noindex, nofollow. Деплой идет одной командой rsync или через GitHub Action. ✅ Полная приватность без ввода логина/пароля (доступ только у того, кто знает 128-битный UUID в URL).
✅ Можно хранить каждую эпоху отдельно: /s/<uuid>/v5/, /s/<uuid>/v6/.
✅ Работают и статика, и Python/Node.js бэкенды (Web Admin, SQLite API).
2. GitHub Pages + Секретный подпуть
(Плагин github уже подключен в нашей среде!)		 Через подключенный инструмент create_github_repository + gh CLI мы можем автоматически пушить сборку в ветку gh-pages в папку со случайным токеном /preview-<token>/index.html. ✅ 0 ₽ затрат на инфраструктуру, мгновенный глобальный CDN, HTTPS из коробки.
✅ Автоматический деплой после каждого прохода Vision Gate прямо из этой ВМ.
3. Cloudflare Pages / Vercel Preview URLs Каждая ветка или коммит получает уникальный неиндексируемый URL вида https://<commit-hash>.<project>.pages.dev. ✅ Автоматическое сравнение версий «Было / Стало» по разным ссылкам.

Готовый конфиг Nginx для VPS с секретной ссылкой (/s/<uuid>/):

location ~ ^/s/([a-f0-9-]{36})/(.*)$ {
    alias /var/www/secret_previews/$1/$2;
    add_header X-Robots-Tag "noindex, nofollow, noarchive" always;
    add_header Cache-Control "no-store, must-revalidate" always;
    index test_benchmarks_showcase.html index.html;
}

🧠 Технический Аудит: Почему в v4/v5 возникали проблемы с управлением и графикой и как они устранены в v6

Симптом у пользователя Корневая техническая причина Решение в v6
1. Превью в браузере продолжало показывать старый интерфейс v4 (на вашем скриншоте) Когда скрипт python3 build_showcase.py перезаписывал файл артефакта из bash-терминала, интерфейс Antigravity не получал сигнал обновления карточки артефакта и показывал закэшированный v4. Финальная публикация артефакта теперь выполняется напрямую через системный инструмент write_to_file с метаданными ArtifactMetadata, что принудительно обновляет панель превью.
2. В Танчиках, Wolf3D и Марио персонаж сам ехал/стрелял, а клавиши стрелок не слушались Во всех играх по умолчанию стоял флаг aiBot = true (режим демо-бота), а элемент <canvas> не имел tabindex="0" для захвата фокуса внутри iframe. В Танчиках функция snapX/snapY вдавливала хитбокс 24x24 в кирпич. Во всех играх установлен aiBot = false (100% ручной режим со старта), добавлен tabindex="0" + перехват capture: true для e.code, e.key и e.keyCode, уменьшен внутренний хитбокс танка до 16x16 с анти-клином и добавлены кнопки пульта с удержанием (onpointerdown).
